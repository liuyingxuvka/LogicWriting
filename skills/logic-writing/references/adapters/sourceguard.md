# SourceGuard adapter

SourceGuard owns the next-search/action policy and evidence-discovery depth.
Logic Writing supplies the claim contract, source roles, existing observations,
access constraints, and stopping needs; it consumes SourceGuard's native result
without copying its planner.

Invoke this semantic owner through `researchguard source` and bind the handoff
to `primary:researchguard:source`. Preflight the single console on every run;
there is no member import, module command, checkout locator, or alternate
member path. Preserve `candidate`, `observed`, `access_gap`, `bounded`,
`planning_only`, `provider_unavailable`, and the native status exactly.
Only observed source content with resolvable lineage may enter factual support.
Preserve the member's native result as it is; never write one on the
member's behalf.

Save the native report: `researchguard source stop-decision <project> > sourceguard-stop.json`. List `{"provider":"sourceguard","path":"sourceguard-stop.json"}` in the closure input's `provider_reports`.

In a brief request, optionally set `sourceguard_model` to the native model YAML
(path relative to the request file). Missing anchor IDs are imported with source,
locator, summary and source boundary as `support`; handwritten rows always win.
Write `limit`, `counter` or `context` rows yourself. This reads the saved YAML;
it neither invokes ResearchGuard nor consumes a converted export.
